# Contributing to JST Stack

Thank you for improving JST. Start with an issue or discussion when a change alters public behavior, architecture policy, generated output, or compatibility.

## Before a pull request

1. Read the affected repository's README and `AGENTS.md`.
2. Keep the change focused and preserve existing public contracts unless the proposal explicitly changes them.
3. Add the smallest test that fails without the change.
4. Run the repository's complete `npm run check` or documented equivalent.
5. Update public documentation and changelog when behavior changes.

Pull requests must explain the problem, chosen solution, verification, compatibility impact, and operational risk. Do not commit secrets, reports, build output, or unrelated generated files.

Questions belong in [Discussions](https://github.com/jst-stack/jst/discussions). Reproducible defects belong in Issues. Breaking or ecosystem-wide changes require an RFC discussion first.

Read [AI_ASSISTED_CONTRIBUTIONS.md](AI_ASSISTED_CONTRIBUTIONS.md) when an AI tool materially assisted the contribution, and follow the [Code of Conduct](CODE_OF_CONDUCT.md) in every project space.
