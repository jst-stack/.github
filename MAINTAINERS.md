The project is currently seeking reviewers through sustained, focused contributions. Maintainer and reviewer responsibilities are defined in [GOVERNANCE.md](GOVERNANCE.md).

## Onboarding checklist

When a reviewer is nominated as a maintainer, an existing maintainer must complete and record this checklist in the nomination issue:

- verify sustained contributions and sound review judgment;
- review governance, security disclosure, AI contribution, and release policies together;
- grant the minimum GitHub and npm roles needed for the accepted responsibilities;
- perform one paired issue triage, pull-request review, and dry-run release;
- confirm access to private security advisories without sharing credentials;
- add the maintainer and explicit ownership areas to this file and `CODEOWNERS`;
- set a six-month ownership review date.

Offboarding removes repository, npm, and security access before ownership is reassigned. The departing maintainer documents active releases, private advisories, and decisions that need a successor; credentials are never transferred between people.
